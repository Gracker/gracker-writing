# 中文技术文档组织（采用稿）

参考阮一峰《中文技术文档的写作规范》，公共领域。
来源：https://github.com/ruanyf/document-style-guide
采用版本：`571951731efb4b83b1939af1d3dd830441ebef45`（原记录抓取于 2026-09-25）。

本文件是为说明性文章整理的采用稿，不代表原规范全文。软件手册的目录、文件命名和篇幅要求不自动适用于博客、个人记录或社交稿。

## 标题与层次

标题帮助读者定位内容。按文章体裁使用连续、清楚的层级；短文不必为了完整而增设章节。同级标题尽量处在相近的概念层次，不要求都写成同一种句式。

标题重名、孤立小节或层级过深时，先看是否增加理解成本，再决定合并或降级。不要因为只有一个子标题就删除有用的分组。修改标题时检查目录、内部链接和外部依赖的锚点。

## 段落与句子

围绕读者能跟上的思路分段。一个段落可以包含判断、依据和必要的限制；转向另一个问题时再换段。不能用渲染后的行数决定段落是否合格。

解释性文字常适合先给重点，再展开理由。悬念、回忆和排查过程可以采用其他顺序，不能为了“中心句在段首”破坏叙述。

长句如果让主语、条件或因果关系难以辨认，可以拆开。被动句、双重否定和名词化本身不是错误；修改前先确认含义和强调重点，尤其别把“并非全部失败”改成“全部成功”。

指代不清、修饰关系混乱或动作主体缺失时，补清对象。优先解决读者具体会误解的地方，不按字数或词性判句子合格。

## 阅读与检索

- 列表用于并列项、步骤或索引；表格用于需要横向比较的内容。保持同一层级的关系清楚，不强求每个条目都是完整句子。
- 说明必要的前置条件、输入与输出。排查文把观察和下一步判断连起来；参考手册可以保留便于检索的条目结构。
- 术语首次解释到什么程度取决于读者。后文稳定使用，不为显得丰富频繁换称呼。
- 引用、图片与关键材料给出可追溯来源。引用块与作者自己的说明应能区分。
- 链接文字说明读者会看到什么；改稿后检查交叉引用是否仍指向正确内容。
