# 中文技术文档写作规范（采用稿）

来源：阮一峰《中文技术文档的写作规范》，公共领域。
仓库：https://github.com/ruanyf/document-style-guide
抓取：2026-09-25，commit `571951731efb4b83b1939af1d3dd830441ebef45`

本文件是写入本 skill 的采用稿，不是原文逐字拷贝。产品手册目录、文件名规范不迁入。与 `copy-editing.md`、`chinese-copywriting-guidelines.md` 冲突时，以那两份和本文件「本 skill 放宽」为准。

## 本 skill 放宽

- 单句 40 字硬限制不作为 L1。技术长句可以超过，但必须在装信息，不能是形容词堆叠或欧化从句。逗号隔开的每一截尽量在 20 字以内。
- 「不使用非正式语言」收成：不用网络流行语、不用感叹加重。活人感和真实工作流痕迹按 `human-feel.md`，不要求写成公文。
- 软件手册结构（简介 / 快速上手 / API / 附录）不套到公众号、系列长文、社交稿。

## 标题

- 层级连续：一级下不能直接出现三级。
- 同级标题不要只有一个（孤立编号）；能省略就收到上一级。
- 下级标题不重复上级标题名称。
- 常规文章控制在三级以内。三级下的并列内容优先用列表，少用四级标题。

## 句子

- 优先简单句、并列句、肯定句、主动语态。不用双重否定。
- ❌ `请确认没有接通装置的电源。` → ✅ `请确认装置的电源已关闭。`
- ❌ `假如此软件尚未被安装，` → ✅ `假如尚未安装这个软件，`
- 用对「的 / 地 / 得」。
- 「其 / 该 / 此 / 这」必须能唯一指代。指代含糊就重复名词。
- 名词前不要叠一串形式词。能拆句就拆句。

## 段落

- 一段一个中心。中心句放段首。
- 段落尽量不超过 7 行，最佳不超过 4 行。
- 用陈述、肯定语气，不用感叹语气。
- 段落之间空一行，段首不空两格。
- 引用第三方文字、转载、外部图片必须标明出处。

## 英文处理

- 英文复数译成中文时还原成单数：`RAMs` → `RAM`。
- 中文里的省略用 `……`，不用 `...`。
- 中文书名、文章名用《》；英文整句书名保持英文习惯，见排版指北。
- 第一次出现的英文专名可在括号里给中文；后文稳定复用，不要换一堆别称。
- 专有名词按官方大小写，非专有名词不要每个词都大写。

## 数值

- 阿拉伯数字用半角，不用全角 `１０００`。
- 4 位以上数值可加千分号；技术稿 4 位数可写 `1000`。
- 范围用 `～` 或「至」，两个数字都带单位：`132 kg～234 kg`、`67%～89%`。
- 「增加了」是增量，「增加到」是定量。不能写「降低 N 倍 / 减少 N 倍」，改成「降低百分之几」或「减少到原来的几分之几」。这条与 `copy-editing.md` 的数字表达一起执行。

## 标点

- 中文句子用全角标点；整句英文用半角标点。
- 句号、问号、叹号、逗号、顿号、分号、冒号不得出现在一行之首。
- 标题末尾不用句号、逗号、顿号、分号、冒号。
- 中文并列用顿号 `、`，即使并列项是英文：`Google、Facebook、腾讯`。
- 补充说明用全角括号 `（）`，括号前后不加空格。
- 解释用全角冒号 `：`；时刻用半角冒号 `8:00`。
- 省略号用 `……`，不与「等」连用。
- 尽量不用感叹号，禁止 `！！`。
- 破折号若使用，占两字宽 `——`，或前后加半角空格的 ` —— `。技术稿能直说就不要靠破折号解释。
- 复合词、图表编号用半角连接号 `-`：`图 1-1`。

## 交付前扫描

只扫可见正文，不要扫代码块、行内代码、URL、路径、trace 名。

```
其直接|受其|该该|此此
没有[^。\n]{0,20}不
尚未被|被安装|被调用
降低了? *\d+ *倍|减少了? *\d+ *倍
！！|？？|。。。|\.\.\.
```

标题再人工看：是否跳级、是否孤立、是否与上级同名。
