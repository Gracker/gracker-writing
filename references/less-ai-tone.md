# 去 AI 味（语料层采用稿）

来源：`larashero3-dotcom/lieflat-less-ai-tone`（MIT，Copyright (c) 2026 shiujan）。
仓库：https://github.com/larashero3-dotcom/lieflat-less-ai-tone
本地安装：`creative/lieflat-less-ai-tone`（完整 `SKILL.md`、`RESEARCH.md`、测量脚本）。
抓取：2026-09-25，commit `27d29232f10124db904ca9c0536d0b67cb3b2833`

本文件不是原文搬家。只迁对 Gracker 写作有执行意义的部分：分层、白名单、信息守恒、11 条可定位规则，以及被语料推翻、精修时不得再当 AI 味去改的条目。

## 两层不要混

| 层 | 管什么 | 主文件 |
|---|---|---|
| 语料层 | 统计上站得住的 AI 痕迹 | 本文件 |
| 作者层 | Gracker 要什么样的技术稿和社交稿 | `human-feel.md`、`style-rules.md`、`social-output-gate.md` |

写作/生成走作者层：具体、不升格、不矫饰、术语稳定、社交稿能直接发。
精修/去 AI 味走语料层：白名单，信息不增不减，未命中的句子逐字保留。

冲突时：

- 精修以本文件为先。不要为了「像人」补口语、调句长、删问句、删比喻、改被动句。
- 作者层仍然生效的只有这些：矫饰性表达（技术机制能直说就直说）、意义通胀、同义词轮换、填充词、技术稿里的悬空动作动词、社交稿导演句/空比较。
- 作者本来就爱用的标点、问句、短句、重复术语，不是 AI 痕迹。

完整实测、被推翻的预设和测量失误见独立 skill 的 `RESEARCH.md`。语料未公开，数字不可第三方复核；采用的是可定位规则和改写约束，不是把频率表抄进词库。

## 精修硬边界

1. 只能改下面 11 条点名的问题。没有命中的句子逐字保留。
2. 命中了也只改解决问题所需的最小范围。不得顺便润色。
3. 标题层级、章节顺序、段落顺序、列表、表格、引用、代码块位置不动。
4. **信息守恒**：不增姓名、数字、日期、引语、来源、因果、场景；不删观点、结论、限定词。把「可能提升」改成「提升」是篡改判断，不是去 AI 味。改写后每个实词都要能在原文指出出处。
5. 原文抽象就保持抽象。不许为了「更具体」自己造数据。第 8 条只允许把原文已有的数字提到概括词的位置。
6. 没把握就保持原文。

## 不作为改写理由

这些看起来像 AI 味，语料站不住。精修时禁止据此改文字。

- 句长、段长不够参差。早期「均匀 51 倍」是切句缺陷。不要为制造节奏调句长或拆段落。
- 单字虚词偏少（就/很/了）。方向是补不是删，补了无法验收，还容易把技术稿改成口语。
- 反复写全称、少用代词。人类更常重复同一名词。这支持作者层的「术语不要轮换」，不支持「多换代词」。
- 被动句、名词化、长句本身。现代汉语书面语的正常写法。
- 正文「首先……其次……最后」、句中「第一，」。第 6 条只管小标题连续编号。
- 句内同构排比（「更高效、更专注、更有创造力」）。只处理相邻句同一骨架，见第 3 条。
- 问句、设问、问句小标题。正文问句人类远多于 AI，删了更不像人写。
- 比喻本身、比喻独立成段。人类用得更多。只处理理想化拟人喻体，见第 7 条。
- 把「能顺翻回英文」当成翻译腔。这不是可定位规则，精修禁止用这条整段重写。

作者层的「不凑三项」仍然有效：那是禁止为节奏编造没有信息增量的第三项，不是禁止句内排比。

## 11 条（按优先级）

改写示例只说明骨架，不要把示例里的「真正」之类填充词学回去。技术稿命中后，改完仍要过 `style-rules.md` 的填充词判断。

### 1. 翻案腔

先立一个读者没有的误解，再推翻。字面包括「不是……而是」「并非……而是」「不在于……而在于」「与其说……不如说」「表面……实际」「看似……实则」「不是 A，是 B」「你以为……其实」「回头才发现」「说到底」「答案恰恰相反」「A 不重要，重要的是 B」。换字面还是这个动作，也要改。

改法：直接从正面下判断。只有正文真的用材料走过误解→修正，才允许自我修正，且不套固定句式。

生成时「不是 X 而是 Y」这一族仍最多 2 次；精修时假翻案全部改掉，真实对照可留。

### 2. 顿号罗列过密

一个分句里两个以上顿号、三项以上并列。能概括就概括；必须保留三项时，改其中一项句法。法规、配置项、财务科目和 Markdown 列表内部不改。

### 3. 相邻句结构同款

相邻两句以上：逗号数量相同、成分顺序相同、长度接近。打散其中一句。不动段落顺序，不删信息。

一段里三个以上平级案例、看得出在凑数时，可合并同类项或压缩次要项。叙事推进（先发生什么、怎么做、结果如何）不算。清单、步骤、条款不改。

「偏好凑三个」本身不成立。不要因为看见三个例子就压缩。

### 4. 揭晓式破折号

用破折号停顿后揭晓，或插入不必需的补充。改成完整句，或改用逗号、句号。作者习惯用破折号、且句意需要时不改。模型差异极大，只按触发认，不按「某模型的味」套。

### 5. 冒号：只改两种

- **提示语冒号**：冒号前是「一句话总结 / 核心是 / 关键在于 / 原因如下 / 结论 / 本质上 / 换句话说」。提示语无信息就删，直接写内容；在承接上文时只换标点，不删前半句。
- **空转句引列表**：一行以冒号结尾，紧接列表，删掉这句信息不减。改成有内容的判断，或删掉空转句。列表项不删。

不改：引语冒号、小标题冒号、列表项内部、总说加分说（「人擅长的是：判断业务逻辑」）、网址和代码。句中冒号总量人类内部差 6.6 倍，不能当 AI 痕迹。

作者层的「形容词 + 冒号起手」（逻辑很清晰：……）仍然要改，那是评价词抢读者判断，不是本条。

### 6. 序数词当小标题

小标题以「一、二、三」或「第一、第二」连续三个以上。只删编号，不改标题措辞、顺序、层级。Markdown 有序列表、步骤指代（「见第三条」）、正文「首先其次」不改。

### 7. 理想化拟人喻体

「像 / 相当于 + 一个 / 一位 + 职业角色」，且带褒义修饰或「不仅……更……」。改成这东西实际做什么。

不改：比喻本身；具体的人当喻体（老师傅、医生朋友）；删掉比喻会丢信息时；文学体裁按原风格。

技术稿作者层仍优先字面说法。精修不要把所有比喻当 AI 味清掉。

### 8. 概括盖住已有数据

同段或邻段已有数字、时间、对象，却写「显著提升 / 大幅增长 / 明显改善 / 效率的提升」。把具体值提到概括词位置。

「完成了对……的……」「实现了……的提升」「进行了……的优化」恢复成动词。原文没有数据时只恢复动词，不许编数字。只有概括、没有材料时不改，可提示作者材料稀薄。

### 9. 禁用起手式

「说白了」「说穿了」「先说结论」。删掉，直接给判断。作者层的「最值得看」仍单独禁止。

### 10. 翻译腔只留五种

未列出的即使读着生硬，精修也必须保留。专业术语、法律、公文、固定译法不改。同一句命中多条时，按出现顺序改一条，不叠加。

1. **过长前置定语**：中心名词前修饰超过十五字，或「的」连续两个以上。拆成两个分句。
2. **「当……时」**：句首「当」+ 完整主谓 +「时，」。删「当」「时」，从句改成分句。时间关系会变模糊时不改。「的时候」不是这条。
3. **前置话题壳**：「对于……来说 / 对……而言 / 就……而言 / 关于…… / 在……方面」，而后文本来就以该对象为主语或宾语。把对象放到主语位。删了会变成全局断言时不改。
4. **句首连接词**：段首或句首「然而 / 因此 / 此外 / 与此同时 / 换言之 / 总而言之」。移到主语后。论证需要显式转折时不改。**不要改成「其实」**——作者层把无对照的「其实」当口水词。
5. **「这意味着 / 这表明 / 这说明 / 换句话说」复述**：后文与前句同义则并入或删提示语。后文有前句推不出的新结论时不改。

不收：以一种……的方式、扮演……角色、使得……能够、被认为 / 被视为、存在着、在某种程度上。这些是翻译腔，但不是 AI 区别性特征。

作者层仍处理：技术稿里的悬空动作动词（接住、击穿、立住），以及把 `context/state/cache` 留在中文里。那是 Gracker 技术稿可读性，不要写成「语料证明这是 AI 味」。

### 11. 段首零主语评论

非首段以「听起来 / 看起来 / 说白了 / 值得注意的是 / 更重要的是 / 关键在于 / 问题在于 / 意味着 / 不难看出」开头，且没有「这 / 那 / 其 / 此 / 上面」等回指。补回指，多数加一个「这」。

首段、已有回指、对话引语不改。比喻独立成段不删，缺回指就补「这」。

## 生成时怎么用

写新稿不要把 11 条当成唯一目标。仍按 `SKILL.md` 的结构、证据、Android 术语和社交把关写。写完再按本文件扫一遍。

生成阶段额外收紧：

- 不要开篇翻案，不要「一、二、三」当小标题通篇编号。
- 不要空转句引列表（「典型场景：」后面接列表）。
- 不要「像一位智慧的导师」。
- 同段已有数字就不要再写「显著提升」。
- 新段落评论上一件事时，把对象或「这」写出来。

不要做：为参差拆句、补「就/了」、把问句改陈述、把三项并列改成两项只为躲「三项」、把被动改主动只为去 AI 味。

## 精修验收

- 每处改动能指出本文件的编号。指不出就撤销。
- 未命中句子逐字保留；框架未动。
- 没有新增事实，没有加重「可能 / 通常 / 据说」。
- 没有为节奏调句长，没有删问句，没有补虚词，没有把句内排比当 AI 味。
- 翻译腔只动了五种，且能指出触发标记。
- 技术稿的矫饰、意义通胀、术语轮换仍按作者层处理，但不得借机改判断或补材料。
