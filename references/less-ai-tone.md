# 局部表达诊断

用于“去 AI 味”和词句润色。目标是修复空泛、重复、歧义和生硬表达，不是模仿某个检测器偏好的分布。

https://github.com/larashero3-dotcom/lieflat-less-ai-tone

其语料未公开，不把统计观察当成可复核的普遍定律。这里只保留有助于定位问题的观察和含义保全原则，不要求安装来源 skill，也不把它的条目当作唯一可修改范围。

## 先判断问题，再决定改法

| 线索 | 需要确认的问题 | 处理方向 |
| --- | --- | --- |
| 先否定再揭晓 | 是否凭空替读者设了一个错误理解 | 没有真实对照就直接说判断；保留真实纠错和自我修正 |
| 泛化评价后接事实 | 评价是否重复事实，或把局部效果拔高 | 让已有事实承担说明作用；必要的作者态度可留 |
| 连续同构句、长串罗列 | 是否让关系难以辨认，或包含重复项 | 按关系合并、拆句或保留；不为躲“三项”改内容 |
| 提示语与冒号、破折号 | 是否只为悬念停顿，删掉后更连贯 | 修改完整句子；保留引语、解释、导航和原有停顿 |
| 长定语、话题壳 | 主干是否被遮住，指代是否清楚 | 局部拆句或前移对象，保留限定关系 |
| 连接词与复述句 | 前后是否真有因果、转折或解释 | 关系需要就留；空转就压缩，不按位置机械移动 |
| 零主语或含糊代词 | 读者是否需要猜对象 | 补清对象；省略没有歧义时不强加主语 |
| 中英夹杂、字面直译 | 是否造成误解或阅读障碍 | 用目标语言自然表达，保留术语与专名 |

这不是穷尽清单。明确的错字、病句、误译和上下文断裂也应按用户授权修复。

需要具体参照时，读取[词组与改写案例](writing-examples.md)：先看常见词组，再看材料、待改句、改法和保留条件。案例中的数据与经历不能补进当前稿件。

## 不足以单独触发修改的形式

第一人称、问句、比喻、被动句、名词化、长句、编号、三项并列、重复术语、某个副词多次出现，都可能是正常写法。能顺畅翻回英文，也不能证明中文有问题。

需要修改时，说清具体影响：指代不明、关系混淆、信息重复、语气失真，或超出材料。不要只写“读着像 AI”。

## 改动边界

- 保留事实、判断、条件、否定、时间与不确定性。词语可以换，含义和语气强度不能暗中换。
- 原文没有数字、实验或来源，不能为“更具体”补造。可以指出材料缺口。
- 优先修改能解决问题的局部，不把一句生硬当成整篇重写的理由。
- 保留承担转折、强调或关系的词。删除提示语后回读整句，不能留下残句。
- 原文自然就不改；不能确定原意时保留或询问，不猜作者想说什么。

例如，材料只有“保存为草稿，尚未发布”，把它写成“已成功上线”是含义错误；把它写得更短，也必须保留“尚未发布”。这是编辑边界，不是某个项目的发布流程。

## 复核

对照改前改后：信息是否减少或凭空增加，主语和归属是否变化，限定是否丢失，原有声音是否变平。解决了什么问题应当能在上下文里看出来，不需要给每处改动分配规则编号。
