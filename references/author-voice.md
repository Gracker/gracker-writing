# Gracker 的作者声音

这份文件描述跨文章可辨认的写法，不规定每篇都要出现哪些元素。具体项目、工具、人物和经历来自本次材料，不能从风格样本移植。

## 保留什么

| 特点 | 写作与改稿时的判断 |
| --- | --- |
| 从手头问题出发 | 保留为什么碰到这件事、为什么值得写；不把具体起因替换成通用背景。概念文也可以直接解释问题，不必硬编故事。 |
| 把判断过程讲出来 | 观察、尝试、意外结果和下一步之间有关系。别只留下正确结论，删掉读者理解结论所需的过程。 |
| 承认有限与没做成 | 没想清楚、没验证、试过没走通、计划没完成，都可能有价值。它们不应被润色成能力宣言或通用建议。 |
| 有自己的判断 | 说清赞同、反对或取舍的理由，保留“当时怎么看”与“现在知道什么”的差别。第一人称用于承担判断，不是装饰。 |
| 与同行说话 | 称呼、设问、括号、自嘲和随口评论可以拉近距离。看它在段落里做什么，不按频次、标点或词库决定去留。 |
| 工作之外也有生活 | 家人、朋友、兴趣、日常烦恼能交代作者的处境。它们不必充当技术论据，也不必被塞进每篇文章。 |

这些特点可以只出现一两种，也可以完全不显露。发布说明、教程、读书札记和年度记录本来就不该同一种口气。

## 原稿中的具体例子

下面的片段来自已核对的历史原稿，用来解释上面的风格判断。保留原始措辞与标点，不把它们当成当前技术结论、通用教程或其他稿件可借用的经历。

### 真实失败不要改成无人的规范建议

原文：“试过用db4o这种对象数据库来进行存储，发现行不通”。[通知中心实战原稿](https://github.com/Gracker/Blog/blob/faa1ed543aec17bf8f0c8a1f1348f888c3f6784d/Blog/source/_posts/android-service-build-your-own-notification-servers-app.md)

若只留下“应选择合适的持久化方式”这样的建议，尝试过什么、哪里没走通就丢了。恢复时可以写“我当时试过用 db4o 保存这个对象，没走通”，再接已有依据支持的纠错。不能由这次失败恢复出“所有情况下都不能持久化”的结论。

### 随口一句也有作用

原文：“已经完成了,没有下一步了.” [源码阅读文章原稿](https://github.com/Gracker/Blog/blob/faa1ed543aec17bf8f0c8a1f1348f888c3f6784d/Blog/source/_posts/view-android-source-code-with-androidstudio.md)

这句话承接操作结束，有一点玩笑和与读者说话的感觉。没必要统一换成“至此，配置流程完成”。保留时确认当前步骤确已结束；旧命令、版本或文件名有误，仍需单独纠正。

### 生活旁白让体谅有了来处

原文：“媳妇做这一块 6 年多了, 晚上加个鸡腿...”。[三星案例原稿](https://github.com/Gracker/Blog/blob/faa1ed543aec17bf8f0c8a1f1348f888c3f6784d/Blog/source/_posts/samsung_crash.md)

前文谈开发者的辛苦，这句说明作者的体谅与身边的人有关。缩成“开发者很辛苦”会丢掉这层关系。它可以保留在原文里，但不能据此要求技术稿都补家人、年限或生活趣事。

### 提示语不能按子串删除

原文里的“也要说实话。”后面谈哪些人可能感受不到这个工具的价值。[实践文章原稿](https://github.com/Gracker/Blog/blob/6dabce4363c4b33928a8153d78fbb2f2422f207c/Blog/source/_posts/OpenClaw-Local-Practice.md)

这句话承担转折与坦承。机械删除“说实话”会留下“也要。”，既成残句，也丢掉作者的态度。即使某处提示语确实多余，也要完整处理整句，再连着上下文回读。

## 写新稿

用用户给的事实和判断建立作者站位。没有亲历材料时，可以解释资料、比较方案、指出未知；不要冒充测试者或补写心理活动。

借鉴的是选择材料和解释问题的方式，不是复制口头禅。自然的短句、长句、重复、玩笑和比喻都可以使用，前提是适合这篇文章，而非为了证明“有人味”。

## 恢复旧稿

1. 找到用户认可的原文或可信历史版本。最新版本未必就是原稿。
2. 比较表达功能：删掉的是经历、判断、读者关系，还是重复与错误？先说清损失，再决定是否恢复。
3. 已确认的事实纠正继续保留。可以写清“当时试过但没成功”，不能因此恢复错误的普遍结论。
4. 保持说话者身份。作者自己的经历不改成第三方的“原文尝试”；他人的经历、引用和编辑补注也不能改成作者亲历。
5. 连同前后段回读。恢复一句话后，要确认转折、指代和时间关系仍然成立。

有依据的恢复允许补回被删内容；这不等于自由扩写。依据缺失时说明缺口，只做现有材料支持的修改。

## 中英文一致性

翻译保留作者在说什么、为何这样想、语气有多重，不只保留结论。具体细节不能默默概括掉，犹豫不能译成确定，玩笑不能变成无意的事实断言。

字面直译不自然时，找目标语言里作用相近的表达；找不到时宁可朴素。不要为译文添加中文没有的戏剧性或新经历。
