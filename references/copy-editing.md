# Technical Copy Editing Rules

这份文件补足中文技术长文的基础校对规则。它参考中文技术文档写作规范，但只保留适合长文、教程、FAQ、工具复盘和系统机制文章的部分；文档首页、按钮文案、移动端表格等产品文案规则不迁入这里。

## 适用边界

这些规则只处理**可见正文**，不要机械改动以下内容:

- 代码块和行内代码
- JSON 键名、数据库字段名、配置项、命令参数
- URL、API 路径、文件路径
- trace event 名称、线程名、counter 名称、slice 名称
- 用户或外部文档明确指定的拼写、大小写和原文引用

校对顺序:先识别内容类型和机器可读边界，再处理标点、称呼、留白、大小写、错词和数字表达。

## 项目覆盖规则

通用 skill 不硬编码某个项目的品牌语气、版本展示、术语表或信息架构。遇到项目专属约定时，按以下顺序处理:

1. 优先读取用户提供的项目文档、术语表、写作规范或现有文章。
2. 如果仓库里已有 `references/Project-Overrides.md`、`docs/style-guide.md`、`AGENTS.md` 等项目规则，按项目规则覆盖通用规则。
3. 如果只是某篇文章里的临时约定，只在本次稿件内保持一致，不上升为通用规则。
4. 如果要沉淀为长期规则，单独放进项目覆盖文件，不混进 `style-rules.md` 或本文件。

判断标准:这个词或写法离开当前项目是否仍然成立?成立才适合进入通用规则;只在当前项目成立,就放项目覆盖规则。

## 标点和称呼

- 中文可见正文里的引用优先用直角引号 `「」`。代码、命令、字段名、英文原文和带格式的术语说明保持原样。
- 不用连续感叹号、省略号或宣传口号式断句。技术判断靠证据，不靠标点加重。
- 正文尽量避免直接称呼 `你`、`您`、`同学`。可以改成 `读者`、`开发者`、`工程师`、`团队`、`排查者`，或改成无主句。
- 引导动作可以保留自然的口语感，但不要写成客服话术、课程话术或训诫语气。

示例:

- ❌ `你只需要看这几行` -> ✅ `重点看这几行`
- ❌ `各位同学可以先看结论` -> ✅ `可以先看结论`
- ❌ `这个优化真的很强！` -> ✅ `这项优化把主线程等待压到了 4 ms 以内`

## 中英文和数字留白

可见正文中，中文与可读的半角英文单词、英文缩写、独立数字和版本号之间保留空格。

推荐:

- `Android 15`
- `HTTP 请求`
- `JSON 字段`
- `API 返回`
- `Perfetto trace`
- `FrameTimeline 数据`
- `提升 5 个百分点`

不要机械加空格:

- `user_id`
- `/api/example`
- `SurfaceFlinger::commit`
- `sched/sched_switch`
- `Choreographer#doFrame`
- `system_server`

判断不清时，优先保持原样并人工判断。不要用批量空格工具直接扫 Markdown。

## 英文状态词和错误词

写接口、日志、错误码或工具输出时，不要机械直译英文状态词。先看语义，再选中文。

- `Success`:不默认写 `成功`，可按语义写 `已完成`、`已处理`、`请求已受理`
- `Invalid`:不写 `非法`，可写 `无效`、`格式无效`、`有误`、`校验未通过`
- `Available`:按语义写 `可获取`、`可访问`、`可使用`、`已开通`
- `Unsupported`:写 `不支持该类型`、`当前不支持`、`暂不支持`
- `Pending`:写 `待处理`、`处理中`、`待确认`
- `Missing`:写 `缺少`、`未提供`
- `Forbidden`:不机械写 `禁止`，可写 `无权限访问`、`当前不允许访问`
- `Unauthorized`:不机械写 `未授权`，可写 `未登录`、`认证未通过`、`缺少认证信息`
- `Bad Request`:不写 `错误请求`，可写 `请求参数有误`、`请求格式有误`
- `Conflict`:不机械写 `冲突`，可写 `状态冲突`、`资源状态不一致`、`请求与当前状态冲突`
- `Timeout`:写 `超时`、`请求超时`、`处理超时`

## FAQ 和排查表达

FAQ、故障排查、工具实战类文章优先交付判断路径，不要只堆概念。

- 先说明第一步查什么，再说明异常分支。
- 错误信息要连到观察点:日志字段、trace 轨道、命令输出、配置项或源码位置。
- 每个问题先给短结论，再给证据和边界。
- 同一组问题的标题、句式和信息密度保持一致。

示例:

- ❌ `这个问题和缓存、网络、权限都有关系。`
- ✅ `先看请求是否到达服务端；服务端没有日志时查网络和代理，服务端有日志但返回 403 时查认证和权限。`

## 中文错词和歧义表达

优先写成具体、可验证、不歧义的表达。

- `阀值` -> `阈值`
- `登陆` -> `登录`
- `布署` -> `部署`
- `配制` -> `配置`
- `起用` -> `启用`
- `反回` -> `返回`
- `回朔` -> `回溯`
- `标示` -> `标识`
- `帐户` -> `账户`
- `帐号` -> `账号`
- `截止 2026 年 4 月 12 日` -> `截至 2026 年 4 月 12 日`
- `搜寻日志` -> `搜索日志`
- `即时通信` / `即时渲染` -> `实时通信` / `实时渲染`
- `做为默认配置` -> `作为默认配置`
- `完成授权`（身份校验语义） -> `完成认证`
- `提示工程学` -> `提示工程`
- `模型出现幻听` -> `模型出现幻觉`

数字表达要分清绝对变化和相对变化:

- `缩小了 3 倍` -> `缩小到原来的 1/3` / `减少了 2/3`
- `从 20% 增长到 30%` -> `提高了 10 个百分点` / `相对增长 50%`
- `转化率提升了 5%`（20% 到 25%） -> `提升了 5 个百分点`
- `翻了 1 倍` -> `变为原来的 2 倍`
- `不超过 100 以上` -> `不超过 100`
- `预计大约 3 点左右` -> `预计 3 点左右`

## 最终校对清单

- 可见正文是否误改了代码、字段、路径、URL 或 trace 名称
- 中文引号、感叹号、省略号是否合适
- 是否出现不必要的 `你`、`您`、`同学`
- 中文与英文、数字之间是否需要留白
- 可见技术术语大小写是否统一
- 英文状态词是否按语义翻译
- 中文错词、数字表达和时间范围是否准确
