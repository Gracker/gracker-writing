# Refinement Mode

## 七、精修 mode

用户让你"精修一篇已写好的文章"(不是重写,不是评审)时用这套工作流。

### 精修 vs 重写的边界

| 动作 | 精修 |
|------|------|
| 删冗余词/AI 填充词 | ✅ |
| 改一句话内的否定-纠正结构 | ✅ |
| 修格式问题(硬换行、中英文空格) | ✅ |
| 改单句表达(让它更直接) | ✅ |
| 删一个明显冗余的段落 | 谨慎 |
| 改段落顺序 | ❌ 属于重写 |
| 改章节结构 | ❌ 属于重写 |
| 改作者的技术判断 | ❌ 属于重写 |
| 补充新论点/新证据 | ❌ 属于重写 |

**原则**:精修只动词句,不动结构;只删冗余,不改事实;保留作者原有判断和表达习惯。信息不增不减：不补数字、场景、因果，不加重「可能 / 通常 / 据说」。

### 审查工作流

先读 `references/less-ai-tone.md`。语料层是白名单：只能改那 11 条点名的问题。未命中的句子逐字保留。不要为「像人」补「就/了」、调句长、删问句、删比喻、把被动句改主动。

**Android 技术稿前置判断**:涉及 Android、Perfetto、性能、系统机制时,读取 `references/android-terminology.md`。`渲染链路`、`输入链路`、`Binder 调用链`、`透传`、`兜底`、`落盘` 等词如果能对应具体系统对象和观察证据,不要机械删;如果只是包装表达,再按黑话处理。

**活人感前置判断**:读取 `references/human-feel.md`。精修时不要把稿子改得更整齐、更像总结卡片;目标是保留作者原有判断和真实工作流痕迹,删掉意义通胀、顺手补分析、同义词轮换和格式用力过猛。

**第零步:信息守恒**——改完每个实词都能在原文指出出处。指不出就撤销。

**第一步:语料层 11 条**——按 `references/less-ai-tone.md` 的优先级扫：翻案腔、顿号过密、相邻句同构、揭晓式破折号、提示语/空转句冒号、序数词小标题、拟人喻体、概括盖数据、五种翻译腔、段首零主语。每处改动必须能说出编号。句首「然而/因此」移到主语后，不要改成「其实」。

**第二步:填充词 grep 初筛**
```
真正|本质上|恰恰|其实|显然|众所周知|不言而喻
说实话|事实上|实际上|关键是|重要的是
值得注意|不得不说|需要指出
```
逐处按 3.3.6 判断：有对照对象、删掉会丢信息就保留;无对照对象只是强调就删。

**第三步:作者层技术稿**——悬空动作动词（接住|击穿|立住|锋利）只在中文日常不会这么用时换中性动词。这不是语料层 AI 味。`context|state|cache|claim` 等有稳定译法的英文换成中文。

**第四步:冒号**——形容词起手（逻辑很清晰：）按 3.3.9 删评价词；提示语/空转句按语料层第 5 条。总说分说冒号不改。

**第五步:格式扫描**——硬换行断名词、section 标题里的填充词、中英文空格不规范。再按 `references/chinese-copywriting-guidelines.md` 扫中文与英文/数字粘连、单位空格、`15 %`/`90 °` 错空格、重复标点；按 `references/document-style-guide.md` 看标题是否跳级、是否孤立，以及双重否定、「降低 N 倍」。

**第五步补充:基础校对扫描**——按 `references/copy-editing.md` 检查可见正文和机器可读内容边界,再处理直角引号、第二人称称呼、术语大小写、英文状态词误译、中文错词和数字表达。不要为了统一大小写误改代码、字段、URL、API 路径、trace 名称或线程名。

**第六步:假想读者错误(3.3.2)和结构性元叙述(3.3.8)**——找 `很多人会以为` / `先记住` / `本节只讲` / `放到下一节`。正文「首先……其次」不要删。

**第七步:作者层活人感**——按 `references/human-feel.md` 检查意义通胀、顺手补分析、同义词轮换、为节奏编造的第三项、加粗过度。矫饰：技术机制能直说就直说；不要把所有比喻当 AI 味清掉。

处理原则:能删就删,能换成具体影响就换成具体影响;不要为了「更像人」新增口语化表演。

### 改动优先级

同样的 AI 味在不同位置严重性不同:

1. **最优先**:section 标题里的填充词(最刺眼,标题该最精练)。
2. **次优先**:每节开头第一句、结尾结论句(读者最容易盯到)。
3. **再次**:列表项开头(短句里填充词比例高)。
4. **中等**:段落首句(给段定调的位置)。
5. **最低**:长段落中间(填充词混在长句里不明显,硬改有时反而破坏节奏)。

时间有限时先扫 1-3 档,4-5 档列在备注里交回用户。

### 改动克制

- 改动数量和 AI 味浓度挂钩——原稿越干净改动越少。经过前序审查的稿子控制在 5-10 处以内。
- 不"为改而改":原句读起来自然、信息准确就别动。
- 不统一口吻:作者的表达习惯(偏口语/偏书面、短句/长句比例)是"活人感"的来源。
- 不把具体边角磨平:失败路径、犹豫、取舍、边界条件、读者反馈如果真实存在,优先保留。
- **改完自己回读一遍**,确认没因为删填充词而让句子反而不通。

### 翻译腔：局部拆句，禁止整段归化

精修时翻译腔只处理 `references/less-ai-tone.md` 第 10 条的五种结构。命中后在原段落内拆句或挪位置，不增删含义。

不要因为「读着像能翻回英文」或「圈不出病句但别扭」就整段盖上重写。那条检验没有触发标记，会把正常书面语改掉，并破坏信息守恒。

过长前置定语拆成两句；「当……时」删掉外壳；话题壳把对象放到主语位。改完对一遍事实，确认限定词还在。
